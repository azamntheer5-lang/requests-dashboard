# واجهة قناة الطلبات — مستودع مستقل (Frontend)

واجهة التسجيل العام + لوحة المراقبة، مفصولة بالكامل عن كود البوت.
هذا المستودع **خالٍ من أي كود بوت** — كل التواصل مع البوت يتم عبر
HTTP فقط (خدمة Render) وسوبابس (REST من الـ API Routes).

## لماذا الفصل؟

| | هذا المستودع (الواجهة) | مستودع البوت |
|---|---|---|
| الاستضافة | **Vercel** (مجاني) | Render / VPS |
| طبيعة التشغيل | Stateless — يبنى ويُقدَّم كصفحات | عملية دائمة 24/7 (جلسات Telethon) |
| النشر عند التعديل | push = deploy تلقائي | deploy يدوي/مراجعة |
| الخطر | لا يحمل أي جلسة أو رقم | يحمل الجلسات — لا يُنشر على Vercel أبدًا |

## التشغيل محليًا

```bash
npm install
cp .env.example .env.local   # ثم عدّل القيم
npm run dev                  # http://localhost:3000
```

## النشر على Vercel — خطوة بخطوة (وش تحط بالضبط)

1. **ارفع هذا المجلد كمستودع GitHub مستقل** (بدون أي ملفات من مستودع البوت).
2. فيرسل: **Add New → Project → Import** واختر المستودع.
3. حقول الإعداد — اتركها كما يلي (كلها افتراضية):

| الحقل | القيمة |
|---|---|
| Framework Preset | **Next.js** (يكشفها تلقائيًا) |
| Root Directory | `./` |
| Build Command | `next build` (افتراضي — لا تغيّره) |
| Output Directory | `.next` (افتراضي — اتركه فارغًا كما هو) |
| Install Command | `npm install` (افتراضي) |
| Node.js Version | 22.x (افتراضي فيرسل) |

4. **Environment Variables** — أضفها قبل أول Deploy (من `.env.example`):

| المتغير | القيمة | إلزامي؟ |
|---|---|---|
| `DASHBOARD_PIN` | رمز اللوحة (8 أرقام) | نعم |
| `E3FY2_SERVICE_URL` | رابط خدمة البوت على Render | نعم |
| `SUPABASE_URL` | رابط مشروع سوبابس | نعم |
| `SUPABASE_SERVICE_KEY` | مفتاح `service_role` (وليس anon) | نعم |
| `RENDER_SERVICE_URL` | رابط خدمة المراقبة (اختياري) | لا |
| `TELEGRAM_BOT_TOKEN` | توكن البوت للفحص (اختياري) | لا |
| `GITHUB_TOKEN` / `WABOT_COMMIT_SHA` | تتبع النشر (اختياري) | لا |

   أضِف كل متغير لبيئتي **Production** و**Preview** معًا.
5. اضغط **Deploy**. كل `git push` بعدها = نشر تلقائي.

## هل تعتمد الواجهة على سوبابس؟

- **حاليًا**: نعم للجزء الخلفي فقط (لوحة الإحصاءات تقرأ من Supabase REST عبر
  API Routes — المفتاح السري لا يظهر في المتصفح إطلاقًا).
- **التسجيل العام (الانضمام)**: يتصل مباشرة بخدمة البوت على Render — لا سوبابس.
- إن حذفت سوبابس لاحقًا: تعمل صفحة التسجيل طبيعيًا، واللوحة تعرض بيانات بديلة فارغة.

## البنية

```
src/
  app/
    page.tsx            # الصفحة الوحيدة: تسجيل عام + قفل + لوحة المراقبة
    api/                # API Routes (تعمل كـ serverless على Vercel)
      join/start|verify # جسر الانضمام إلى خدمة البوت
      fleet-data/       # قراءة الأسطول (سوبابس + البوت)
      unlock/           # التحقق من رمز اللوحة
      join-status/      # إحصاءات الانضمام
      wabot-status/     # فحص صحة النشر (اختياري)
  components/           # مكونات shadcn/ui + لوحات
  lib/                  # عملاء HTTP + أنواع
```

## الأمان

- مفتاح `service_role` يُستخدم **فقط** داخل API Routes (server-side) ولا يُشحن للمتصفح.
- رمز اللوحة يُقارن داخل `/api/unlock` على السيرفر — ليس في كود الصفحة.
- الـ headers الأمنية مضبوطة في `vercel.json`.
